# テスト仕様書

三目並べのロジックに対するテストの要件をまとめる。

## 1. テストの対象

| 関数 | ファイル | 対象 | 理由 |
|---|---|---|---|
| `judge` | model.cpp | ○ | 入出力を使わないので、そのままテストできる |
| `toIndex` | model.cpp | ○ | 入出力を使わない (まだテストは無い) |
| `printBoard` | view.cpp | × | `std::cout` に直接出力しているため |
| `playGame` | controller.cpp | × | キー入力を待つため、テストが止まってしまう |
| `retry` | controller.cpp | × | `std::cin` で入力を待つため、テストが止まってしまう |

テストは model (ルール) だけを対象にする。model は画面もキーボードも使わないので、`model.cpp` だけとリンクしてテストできる。

## 2. `judge` の仕様

盤面(9マス)を受け取り、揃っているラインがあればそのマークを返す。

| 戻り値 | 意味 |
|---|---|
| `"x"` | x が揃っているラインがある |
| `"o"` | o が揃っているラインがある |
| `""` | 揃っているラインがない |

- ライン = 縦 3 本・横 3 本・斜め 2 本の計 8 本(`LINES`)。
- 勝ち負けはプレイヤーの視点ではなく、「盤面で何が揃っているか」で決まる。
- `""` は「勝負が決まっていない」という意味ではない。盤面がすべて埋まっていて揃っているラインがない場合(引き分け)も `""` を返す。
- **引き分けの判定は `judge` の役割ではない。** ゲームのループが最後まで回り切ったことで引き分けとしている。

## 3. 未決定の仕様

以下の盤面を渡したときに `judge` が何を返すべきかは、まだ決めていない。

- [ ] x と o の両方が揃っている盤面(通常のゲームでは起きない)
- [ ] x・o・空白以外の文字が入っている盤面
- [ ] マスの数が 9 ではない盤面

## 4. テストの観点

| 観点 | 内容 | 状況 |
|---|---|---|
| ① 同値分割 | 戻り値で `"x"` / `"o"` / `""` の 3 グループに分ける。`""` のグループはゲームの最初・途中・最後で盤面の様子が大きく違うので、分けてテストするか検討する | 整理済み |
| ② 境界値 | 「揃った」と「揃っていない」の境目にあたる盤面を具体的に挙げる | TODO |
| ③ 網羅 | 全パターンを試せるもの(ラインの本数 × マークの種類)を挙げる | TODO |
| ④ エラー推測 | `judge` に関する過去のバグを挙げる | TODO |

### ② 境界値で検討する状況

- [ ] 2 つだけ並んでいる
- [ ] 同じマークが 3 つあるが、一直線ではない
- [ ] 3 マス一直線だが、x と o が混ざっている
- [ ] 3 マス一直線だが、全部空白

## 5. テストケース一覧

| No | 観点 | 状況(盤面) | 期待する結果 | 優先度 |
|---|---|---|---|---|
| | | | | |

- 期待する結果は、コードの現在の動きではなく **2. の仕様** から決める。
- 1 行が 1 つの `TEST` に対応するようにする。テストコードのコメントに No を書いて対応させる。

## 6. 将来やりたいテスト

今の構成ではテストできないもの。ロジックを関数として切り出したときに使う。

- 入力処理(現在は `playGame` の中に `std::cin` と一緒に書かれている)
  - 0〜8 の範囲外の数字を弾く
  - すでに埋まっているマスを弾く
  - 文字を入力されても無限ループにならない(過去のバグ: `std::cin` がエラー状態のまま、バッファに入力が残っていたことが原因)
- 手番の交代(x が先手、その後は交互)
